## Rock 2 — Admin (Codex)
Files: NEW `admin.html` (+ optional paired `assets/admin.js` — Integrator's call). `<meta name="robots" content="noindex,nofollow">`; NOT in nav, sitemap, or robots.txt (a Disallow line would advertise it). Photo input: accept `.jpg,.jpeg,.png,.webp` only; reject sources >20MB OR >8000px in either dimension BEFORE canvas allocation (check via Image natural size).
Auth: password grant via `/auth/v1/token?grant_type=password`; decode the JWT payload and REQUIRE `sub === '696378f9-f9f9-4a72-8f5d-66ec03a09312'` before showing the admin UI (any other valid account → "This account has no access" + logout). Keep `{access_token, refresh_token}` in sessionStorage; on 401 → ONE single-flight refresh (`grant_type=refresh_token`), atomically store the NEW token pair (rotation), retry once; failure → clear + login screen. Sign out: POST `/auth/v1/logout` (Bearer), and clear local session state in `finally` (if revocation fails, still log out locally and show "server sign-out unconfirmed").
CRUD per backend contract. Photo pipeline: input accept jpeg/png/webp; client-side downscale to max 1600px JPEG q0.82 via canvas; cap 12 photos/property; reject sources >20MB with a message; upload SEQUENTIALLY to `/storage/v1/object/natalie-properties/<uuid>.jpg`; store object keys.
Orphan-safe ordering: (create/edit) upload new photos SEQUENTIALLY first — if ANY upload in the batch fails, delete ALL newly uploaded keys and abort with a visible error; then write the row. Row ids are CLIENT-GENERATED (crypto.randomUUID) so outcomes are reconcilable: on a DEFINITE row rejection (4xx) delete the new uploads; on an AMBIGUOUS outcome (network error / timeout / 5xx) do NOT compensate blindly — GET the row by id first and reconcile (exists → success path; absent → compensate). (Edit removing photos) write row first → then delete removed objects; storage-delete failures are non-fatal but MUST show a visible "cleanup incomplete" warning and keep the keys in a retry note. (Delete property) delete row first → then best-effort object cleanup with the same warning rule. After every save: re-fetch list. `updated_at` never sent by client.
**Proof (offline, Codex):** `node --check` on JS; `node backend/check-key.mjs` (scans EVERY tracked .html/.js file: fails on any `service_role` string; finds every `eyJ…` JWT literal, decodes payload, asserts `role === "anon"`); admin.html contains all UI-SPEC §6 fields incl. amenity checkboxes and photo controls.
**Proof (Fable, networked):** Playwright — wrong password → visible error, no session; login with real creds → FULL-FIELD fixture (nondefault status/type/energy/amenities/facts) + BLANK-OPTIONAL fixture, both round-tripped (DB values + public rendering asserted); create property with 2 uploaded photos → REORDER + REMOVE one (persisted key order, public cover, removed object deleted); publish toggle → visible on properties.html; COMPENSATION: (a) row write fails via real constraint violation after uploads → objects cleaned + visible error, (b) second-of-batch upload failure (fetch stubbed) → ALL new keys deleted + abort, (c) storage DELETE failure (fetch stubbed) → keys preserved + visible cleanup warning; TOKEN ROTATION: corrupt stored access_token (valid refresh) → auto-refresh, retry succeeds, BOTH tokens replaced; second TRANSIENT auth user rejected at the admin gate (sub check), 403 on direct insert, cannot read drafts, storage upload denied (user deleted after); revoked session cannot mint tokens; delete property → objects gone (public URL 400/404); 320px viewport: no horizontal overflow on properties.html + admin list/form, amenity rows wrap, modal thumbs scroll; forced portfolio fetch failure (fetch stubbed) → #properties-error visible, empty state absent, teaser hidden; keyboard: card reachable+activatable via keyboard, Esc closes modal, focus returns to the card.
