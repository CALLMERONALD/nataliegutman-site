## Rock 2 — Admin (Codex)
Files: NEW `admin.html` (+ optional paired `assets/admin.js` — Integrator's call). `<meta name="robots" content="noindex,nofollow">`; NOT in nav, sitemap, or robots.txt (a Disallow line would advertise it).
Auth: password grant via `/auth/v1/token?grant_type=password`; keep `{access_token, refresh_token}` in sessionStorage; on 401 → ONE single-flight refresh (`grant_type=refresh_token`), atomically store the NEW token pair (rotation), retry once; failure → clear + login screen. Sign out: POST `/auth/v1/logout` (Bearer) THEN clear storage.
CRUD per backend contract. Photo pipeline: input accept jpeg/png/webp; client-side downscale to max 1600px JPEG q0.82 via canvas; cap 12 photos/property; reject sources >20MB with a message; upload SEQUENTIALLY to `/storage/v1/object/natalie-properties/<uuid>.jpg`; store object keys.
Orphan-safe ordering: (create/edit) upload new photos FIRST → write row → on row failure, best-effort delete the just-uploaded objects; (edit removing photos) write row first → then delete removed objects; (delete property) delete row first → then best-effort delete its objects. After every save: re-fetch list (no trusted local state). `updated_at` never sent by client (server trigger owns it).
**Proof (offline, Codex):** `node --check` on JS; `grep -L 'service_role' admin.html assets/*.js` (no service key anywhere) + key-role check reused; admin.html contains all UI-SPEC §6 fields incl. amenity checkboxes and photo controls.
**Proof (Fable, networked):** Playwright — wrong password → visible error, no session; login with real creds → create property with 2 uploaded photos → publish toggle → row visible on properties.html; edit price → change visible; second TRANSIENT auth user (created via admin API, deleted after) gets 403 on insert AND cannot see unpublished rows AND storage upload denied; revoked session (after logout) cannot mint a new access token; delete test property → storage objects gone (list bucket).
